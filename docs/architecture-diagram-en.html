Agents Orchestration — Architecture Overview

Result-driven orchestration. The framework schedules tasks and collects result contracts only; it does not observe agent internals. Six functional layers over a shared persistence base.

Access Plan Schedule Execute
Govern Learn Persistence Base
Main data flow Learning feedback loop
01 ACCESS System boundary
Every external entry point of the framework: goal submission and task-graph submission, run control and recovery, progress and reports, and review of the complete execution process.
API Gateway CLI client Web pages Embeddable library API
Goal  →  task graph A free-text goal is decomposed; an existing task graph is submitted directly
02 PLAN Goal → task graph
Turn a natural-language goal into an executable, parallelizable, auditable task graph; derive the graph's structural analysis and the agent resource profile.
Task Decomposer Dependency Analysis Resource Collector
Task graph + capability requirements Allocation is driven by the resource profile
03 SCHEDULE Allocate · dispatch · converge
Select an agent instance per task, advance the graph in topological order under the declared resource limits, and converge failures through retry, propagation, pruning, and cancellation.
Resource Allocator DAG Scheduler (sync / async) Failure Handling
Dispatch task_request / info_request Protocol template + request JSON + upstream input
04 EXECUTE Protocol assembly · parsing
Assemble the protocol prompt, invoke the model, and parse the response into a valid result contract. All stability risk — format drift, malformed JSON — is absorbed here, so agents need no adaptation.
Agent Adapter External Agent
Result contract Reconciled by request identifier; late results of cancelled tasks are discarded
05 GOVERN Audit · judge · account
Verify every result contract against the scheduling facts through a deterministic, replayable audit; judge goal attainment against the original goal (advisory); account cost, tokens, and metrics.
Result Auditor Reflection / Judge Cost Accounting Observability
Governance findings attached to the run archive Audit reconciliation · cost · pruning evidence · goal attainment (advisory)
06 LEARN Review · accumulate · feed back
Perform a read-only review at run finalization, classify findings by evidence strength, persist them into a cross-run lesson base, and feed the qualifying lessons back into the decomposition prompt.
Review & Rule Extraction Lesson Base (cross-run) Prompt Advisor
Run archive persisted Process event stream + terminal report (governance and learning findings attached)
BASE PERSISTENCE Cross-layer foundation
Record the framework-side scheduling state as an event stream and the terminal report as an immutable run archive, enabling crash recovery, replay, and review.
State Store Run Archive (event stream + terminal report)
