Agents Orchestration — Architecture Overview

Result-driven orchestration: the framework schedules tasks and collects result contracts only, and does not observe agent internals. Six functional layers over a shared persistence base.

01ACCESSSystem boundary
Sole external entry: submit a goal or task graph, control and recover runs, and read progress, reports and the full execution history.
API Gateway · CLI · Web · Library API
goal → task graph
02PLANGoal → task graph
Turn a natural-language goal into an executable, auditable task graph; derive its structural analysis and the agent resource profile.
Task Decomposer · Dependency Analysis · Resource Collector
task graph + capabilities
03SCHEDULEAllocate · dispatch · converge
Assign an agent instance per task and advance the graph in topological order within resource limits; converge failures by retry, propagation, pruning and cancellation.
Resource Allocator · DAG Scheduler · Failure Handling
task_request / info_request
04EXECUTEProtocol assembly · parsing
Assemble the protocol prompt, invoke the model and parse the response into a valid result contract; format drift is absorbed here, so agents need no adaptation.
Agent Adapter · External Agent
result contract
05GOVERNAudit · judge · account
Audit result contracts deterministically (read-only, replayable), judge goal attainment against the original goal (advisory), and account cost, tokens and metrics.
Result Auditor · Reflection / Judge · Cost Accounting · Observability
governance findings
06LEARNReview · accumulate · feed back
Review each run read-only, grade findings by evidence strength, persist a cross-run lesson base and feed qualifying lessons into the decomposition prompt.
Review & Rule Extraction · Lesson Base · Prompt Advisor
run archive
BASEPERSISTENCECross-layer foundation
Persist scheduling state as an event stream and the terminal report as an immutable run archive, enabling crash recovery, replay and review.
State Store · Run Archive
