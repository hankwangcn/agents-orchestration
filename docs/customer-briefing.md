# 客户介绍讲述文稿 — 系统架构总览讲解

> 用途：面向客户讲解系统总体架构
> 时长：约 6.5 分钟（按每分钟约 250 字口播）
> 配图：架构总览图（七层带 = 六层功能架构 + 持久化底座）

---

## 一、全景（约 35 秒）

本图呈现系统的总体架构，由七条层带构成：六层功能架构与一条跨层的持久化底座。

阅读方向即为一次运行的推进方向：目标自接入层进入，经规划层拆解、调度层分配、执行层调用，由治理层判定，最终在学习层沉淀，全程数据落入持久化底座。

图中三类连线表示主数据流、取消信号与学习反馈闭环，以下逐层说明。

## 二、接入层（约 35 秒）

接入层是系统的边界，对外提供四种入口。API 网关是唯一的 HTTP 服务入口，承载运行全生命周期接口；Web 页面是运行存档的人读界面，完整呈现一次运行的执行过程；命令行客户端将操作暴露到终端与交互式会话；编程式接口以库内嵌方式供上层程序驱动编排。使用方由此提交自然语言目标，或直接提交现成任务图。

## 三、规划层（约 45 秒）

规划层将目标转为任务图，含三个模块。

任务拆解引擎由大模型把自然语言目标转为带数据流依赖的子任务图；每个子任务声明模型、预算、超时与能力标签，作为分配依据。

依赖分析是任务图的结构视图，执行引用校验、无环检测、拓扑分层与并行宽度计算，并给出剪枝所依据的可达关系；该模块为纯结构计算，不持有运行时状态。

资源统计器经信息请求采集各 Agent 的能力、资源与约束声明，形成并维护资源画像，供调度层读取。

## 四、调度层（约 55 秒）

调度层负责分配、派发与收敛，含三个模块。

资源协调器为每个任务选定 Agent 实例，采用三级分配策略：先按模型精确匹配，再退至能力匹配，最后降级并显式记录。

DAG 调度器按拓扑序派发任务并将运行推进至终态。异步实现以事件循环并发推进，把声明中的并发上限与速率配额转为强制执行；单次尝试超时由框架强制中断；失败任务自动重试并指数退避。

失败处理器是跨三层协作的能力，非独立模块：覆盖重试、失败传播、失效任务剪除与统一收尾。剪枝判据为任务的产出是否仍被最终交付消费，据此取消不再产生交付的整棵分支。

## 五、执行层（约 50 秒）

执行层承担协议装配与解析，含 Agent 适配器与外部 Agent 两部分。

Agent 适配器是框架与 Agent 之间的唯一执行入口：完成协议模板装配、调用模型，并对返回结果执行两级校验——先验契约结构，再验产出是否符合任务声明的输出结构，不符即携带原因修正重试。

框架采用提示词即协议的方式，把模板与请求拼接后直接下发，Agent 保持零适配。两者之间仅有两类消息——任务请求与信息请求；Agent 侧硬约束只有一条，即返回合法 JSON。

## 六、治理层（约 50 秒）

治理层进行确定性审计、运行级判定与成本核算，含四个模块。

结果审计器对结果契约与调度事实执行确定性对账，覆盖正确性、分配、剪枝与语义交叉校验，结论分三级；该模块只读、可复跑、确定性。

反思与判定器以运行级原始目标为唯一基准，判定最终交付是否达成目标；判定者优先取独立 Agent，可为异构模型。该结论为参考性质，不改变状态、不阻断交付，与审计分离记录。

成本核算按 Agent 与分配方式归集成本与用量；可观测性提供按运行隔离的指标与结构化日志。

## 七、学习层（约 50 秒）

学习层完成复盘、沉淀与回馈。运行收尾时，框架对同一份报告执行只读复盘并提取规则。规则带证据强度分级：客观规则源自框架自观测的确定性事实，判定结论源自大模型、属非确定结果；两者分层呈现，不作同级并列。

经验库将规则落盘并聚合为跨运行摘要，记录命中次数与贡献运行数——跨运行复现方构成客观依据。

提示词顾问是学习闭环的出口，生成注入拆解提示词的指导块，含注册表实测事实、达复现门槛的客观规则与单独标注的判定结论，回馈下一次拆解。

## 八、持久化底座（约 30 秒）

持久化底座是跨层基础。运行存档为单次运行的不可变记录，由过程事件流与终态报告构成：事件流逐条记录状态变更，可精确回放；终态报告附载治理与学习产物。该存档是系统的唯一权威来源，支持读回与运行枚举，进程重启后仍可查询；崩溃恢复的断点亦由此还原。

## 九、三类连线与结语（约 35 秒）

回到图中连线。主数据流以结果契约为载体贯穿全程；取消信号在失败传播时尽力下发；学习反馈闭环将跨运行的复现规则注入规划层的拆解提示词。

概言之，本系统以单一结果契约为接口、以分层架构组织编排，使任务分得开、异常管得住、经验留得下。后续建议结合客户实际业务场景开展一次针对性验证。
