Agents Orchestration — 架构总览

结果导向的 Agent 编排框架（Result-driven Orchestration）· 仅管理任务与结果，不观测 agent 内部执行状态 · 提示词即协议，agent 侧无需适配
每个模块以「一句话核心功能 + 分步工作流程」呈现

接入层 规划层 调度层 执行层 治理层 学习层 持久化底座
主数据流（结果契约驱动） 取消信号（best-effort） 学习反馈闭环
接入层 ACCESS 系统边界
框架对外的全部入口，覆盖目标提交、进度查询、报告获取与执行过程查阅。
API 网关
核心功能框架唯一的 HTTP 服务入口，承载运行全生命周期的对外接口与后台任务管理。
工作流程
  1. 接收 HTTP 请求，按端点路由至对应能力
  2. 拆解请求（POST /api/decompose）产出任务图；或提交请求（POST /api/runs）接收既有任务图
  3. 任务图落盘为运行存档，返回运行标识
  4. 运行交由后台任务执行，期间持续更新状态与事件流
  5. 查询、治理、恢复类请求从存档读回并返回响应（报告、投影、指标、经验库、agent 档案等）
Web 页面
核心功能运行存档的人读界面，完整呈现一次运行的执行过程。
工作流程
  1. 运行列表（GET /）枚举全部运行
  2. 运行详情（GET /runs/{id}）读取该运行的存档
  3. 由存档投影为人读视图（纯函数，同一存档渲染同一视图，可重放、无额外成本）
  4. 服务端渲染为 HTML 返回；投影按需生成，不落盘为独立数据副本
命令行客户端
核心功能接入能力的命令行形态，将框架全部操作暴露至终端与交互式会话。
工作流程
  1. 解析子命令与参数（仅依赖标准库）
  2. 转换为对应 HTTP 请求发往 API 网关
  3. 接收响应并渲染为终端输出
  4. 无子命令时进入交互式会话
编程式接口
核心功能以库内嵌方式直接驱动编排，供上层程序集成。
工作流程
  1. 构造任务图与 agent 注册表
  2. 选择同步入口（单次运行）或异步入口（并发运行，运行间状态隔离）
  3. 调度器按拓扑序执行并返回调度报告
  4. 调用方按报告读取各任务结果
提交目标 目标文本 → 拆解引擎；或直接提交既有任务图
规划层 PLAN 目标 → 任务图
将自然语言目标拆解为可执行、可并行、可审计的任务图，并给出任务图的结构视图与可用资源画像。
任务拆解引擎
核心功能将自然语言目标转换为带数据流依赖的子任务图。
工作流程
  1. 装配拆解提示词：固定指令 → 学习层指导块 → 用户目标
  2. 调用大模型产出子任务与数据流依赖
  3. 执行拆解 Schema 校验与依赖结构校验（引用合法性、无环、存在交付点）
  4. 不合规时不重放原提示词，改为携带失败原因与正确示例重试一次
  5. 校验通过后返回任务图（属框架内部调用，不经消息协议）
依赖分析
核心功能任务图的结构视图，纯结构计算、不持有运行时状态。
工作流程
  1. 由任务图建立邻接表
  2. 校验引用合法性、检测成环、确认存在交付点
  3. 计算拓扑序（并列节点按插入序，保证确定性）
  4. 计算拓扑分层（并行前沿）与最大并行宽度
  5. 计算可达性与反向可达，供剪枝判据与交付点判定使用
资源统计器
核心功能经信息请求采集 agent 的能力、资源与约束声明，形成并维护资源画像。
工作流程
  1. 登记 agent 实例（agent 标识、模型、适配器引用）
  2. 经信息请求采集能力、资源与约束声明
  3. 解析为结构化声明入库；单点采集失败相互隔离
  4. 池级惰性刷新：画像超过生存期即重新采集，生存期内无额外开销
  5. 派发前决策点校验，复核选中 agent 的易变维度（资源、约束）；采集受框架侧墙钟上限约束
任务图 + 能力需求 资源画像驱动三级分配
调度层 SCHEDULE 分配 · 派发 · 收敛
资源协调、并发派发、失败传播与失效任务剪除。
资源协调器
核心功能为每个任务选定 agent 实例。
工作流程
  1. 精确匹配：按任务声明的模型匹配，同模型多实例轮询分流
  2. 未命中则能力匹配：按能力标签匹配，部分覆盖标记风险
  3. 仍无匹配则降级至默认通用模型，显式记录不静默接受
  4. 连续失败达阈值后摘除该实例，不再参与分配
  5. 全程只读取资源画像，不执行采集
DAG 调度器（同步 / 异步）
核心功能按拓扑序派发任务并将运行推进到终态。
工作流程
  1. 就绪集 = 依赖任务全部成功的任务
  2. 按拓扑序派发，并向任务传递上游结果
  3. 异步实现并发推进：任一派发完成即处理，资源限制由声明转为强制执行（并发上限信号量、速率配额滑动窗口）
  4. 单次尝试超过任务超时即由框架强制中断，产出失败结果汇入重试链路
  5. 失败重试 2 次并指数退避，耗尽后转入失败处理
  6. 竞态按「冻结派发 → 取消 → 统一收尾」处理，迟到结果直接丢弃
失败处理器
核心功能重试 → 失败传播 → 失效任务剪除 → 统一收尾反馈。
工作流程
  1. 任务级重试，不区分副作用声明；副作用任务的幂等责任归执行侧
  2. 重试耗尽后，按反向可达性计算存活交付点
  3. 存活交付点为空则整棵任务图剪除
  4. 对剪枝时仍处于运行中的任务下发取消（best-effort，不阻塞收尾）
  5. 汇总为调度报告的统一收尾
  6. 该能力跨三层协作，不构成独立模块：剪枝算法属图结构计算，取消下发与派发冻结属调度控制流
派发 task_request / info_request 协议模板 + 请求 JSON + 上游输入拼接；由框架侧主动发起
取消变体（best-effort）
执行层 EXECUTE 协议装配 · 解析
协议装配与解析——稳定性风险在本层收敛，agent 侧无需适配。
Agent 适配器
核心功能装配协议提示词、调用模型并解析结果契约，是框架与 agent 之间的唯一执行入口。
工作流程
  1. 装配协议提示词（协议模板全文 + 请求 JSON + 上游输入）；模板分完整版与简化版，内嵌正反示例
  2. 调用模型：异步默认将同步实现交线程池，HTTP 形态实现原生异步
  3. 两级校验：提取 JSON → 校验信封与输出结构
  4. 校验失败携带正确结构自动修正重试一次，与任务级重试分离计数；解析组件为框架内最严格的模块
  5. 从模型 API 响应回填真实用量与耗时
  6. 返回结果契约
Agent（外部）
核心功能接收请求、返回符合结果契约的 JSON，无需为该框架作适配改造。
工作流程
  1. 接收协议提示词请求
  2. 在目标与契约范围内自行裁定全部取舍（含价值性取舍），框架不设征询通道
  3. 输出合法 JSON——唯一强制约束
  4. 返回结果契约；格式漂移、语义漂移与提示注入等风险由框架侧解析组件收敛
结果契约 request_id 对账；被取消任务的迟到结果直接丢弃
治理层 GOVERN 审计 · 判定 · 核算
确定性审计、运行级语义判定（advisory）、成本核算与可观测性。
结果审计器
核心功能对结果契约与调度事实执行确定性对账。
工作流程
  1. 以调度收尾报告为唯一输入，不接收外部运行态
  2. 正确性对账：任务状态与结果契约矛盾、缺失契约、迟到结果
  3. 分配审计（降级与风险）与剪枝审计
  4. 语义交叉校验：能力声明、副作用声明与实际结果
  5. 错误模式归集；结论分三级 ok / warning / critical
  6. 全过程只读、纯函数，不写回被审计报告，同一报告重复审计结论逐字节一致
反思 / 判定器
核心功能以原始目标为唯一基准，判定最终交付是否达成目标（advisory）。
工作流程
  1. 选定判定者：优先取注册表中声明判定能力的独立 agent（可为异构模型），无则按允许自判降级并标记非独立，或跳过
  2. 以运行级目标 goal 为唯一基准，子任务结果仅作证据随附
  3. 组装为一次普通 task_request 调用，不新增消息类型
  4. 输出受结构强校验与解析重试约束，调用受墙钟超时约束，超时或异常一律收敛为错误码
  5. 结论写入报告并供学习层消费；不改变状态、不阻断交付、不自动重派，成本单列，判定产物不再被判定
成本核算
核心功能按 agent 与分配方式归集成本与 token。
工作流程
  1. 按 agent 与分配方式归集成本与 token
  2. 降级成本单独列示
  3. 失败重试的沉没成本与剪枝已发生成本单独列示
  4. 对照 agent 声明的预算上限执行超支判定（预算为 0 时不判定）
可观测性
核心功能按运行隔离的指标聚合与结构化日志。
工作流程
  1. 采集运行事件
  2. 按运行标识隔离聚合指标：成功率、耗时、峰值并发、降级数
  3. 以 key=value 结构化格式记录请求、响应、解析与取消全链路日志
  4. 指标直接供审计与学习层消费
治理产物附载回运行存档 审计对账 · 成本 · 剪枝证据 · 目标达成度（advisory）
学习层 LEARN 复盘 · 归集 · 回馈
确定性复盘 → 证据分级 → 跨运行经验库 → 回馈拆解提示词。
复盘与规则提取
核心功能运行收尾时对同一份报告执行只读复盘，产出分级的规则结论与动作建议。
工作流程
  1. 运行收尾时读取同一份报告（审计对账 + 成本归集 + 判定结论）
  2. 逐条按阈值判定生成规则：REC-1（缺契约、状态矛盾）、FP（同错误码频发）、DEG-1（降级占比高）、CAP-1（风险分配失败率高）、BUG（实花超预算）、PRU-1（剪枝）、INT-1（中断待人工）、JUD-1/JUD-2（目标未达成、判定无结论）
  3. 按证据强度分级：objective（确定性事实，可重放）与 judgment（大模型判定，非确定有成本），禁止同级呈现
  4. 异常一律隔离，不阻断运行收尾
经验库
核心功能将规则落盘并聚合为跨运行摘要，作为后续任务的数据基础。
工作流程
  1. 规则按运行标识与规则标识幂等落盘；同一运行重新执行不重复计入
  2. 按规则标识聚合：命中次数、贡献运行数、最高严重度、最近证据
  3. 单次运行内的阈值统计意义有限，跨运行复现构成客观依据
  4. 经接口对外提供（GET /api/lessons 与 ao lessons）
提示词顾问
核心功能生成注入拆解提示词的指导块，是学习闭环的输出端。
工作流程
  1. 读取注册表实测事实：当前可用模型、已注册能力标签（无需阈值门槛）
  2. 读取达到复现门槛的客观规则（min_occurrences 默认 2），每条恒附「既往 N 次运行命中 M 次」的数值依据与建议动作，条数受限、超长截断
  3. 判定结论单独成节并显式标注非确定来源，客观与判定禁止同级呈现
  4. 生成指导块注入拆解提示词；指导块缺失、空串或异常一律退化为不注入，学习层故障不影响拆解
运行存档落盘 过程事件流 + 终态报告（治理与学习产物附载）
持久化底座 STORE 跨层基础
保存框架侧的调度状态与运行存档，供崩溃恢复、查阅与复盘。
状态存储 / 运行存档
核心功能单次运行的不可变存档，是框架的唯一权威来源。
工作流程
  1. 调度状态变更（启动、派发、完成、失败、取消、剪枝）逐条写入过程事件流，事件驱动写入使数据丢失窗口趋近于零
  2. 运行收尾写入终态报告，治理与学习产物附载其中
  3. 支持报告读回与运行枚举，跨进程重启后仍可查询
  4. 崩溃恢复：读回存档，其中无副作用任务自动重派，声明副作用的任务置为待人工确认
  5. 经验库与叙述摘要为本存储的可选能力，未实现时各自退化为无相应记忆
