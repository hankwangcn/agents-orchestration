Agents Orchestration — 架构总览

结果导向 Agent 编排框架（Result-driven Orchestration）· 只管任务到结果，不监控 agent 内部状态 · 提示词即协议，agent 零适配

接入层 规划层 资源与调度层 执行层 治理层 学习层
主数据流（Result 契约驱动） 取消信号（best-effort） 学习反馈闭环
接入层 ACCESS 框架对外的全部入口——提交目标、查询进度、获取报告
API
API 网关 orchestration/api/gateway.py
FastAPI REST + RunManager：提交 DAG / 进度快照 / 收尾报告 / 运行指标 / 取消 run / agent 档案。框架从「库」到「系统」的入口，协议通信不暴露到 HTTP。
PY
编程式 API orchestration/scheduler*.py
库内嵌调用：Scheduler.run(dag)（同步） / AsyncScheduler.run(dag, run_id, cancel_event)（异步，多 run 并发隔离）。
提交目标 目标文本 → 拆解引擎；或直接提交 DAG JSON（API 网关）
规划层 PLAN 把目标拆成可执行、可并行、可审计的子任务
拆解
任务拆解引擎 orchestration/decomposer.py
LLM 将目标拆解为子任务 + 依赖 DAG（数据流依赖），拆解 Schema 严格校验。每个子任务声明 model / budget / timeout 与能力标签 required_capabilities——这是「谁适合干」的输入。
输出：依赖 DAG能力需求声明Schema 校验
DAG + 能力需求 注册表采集 agent 能力/资源声明（info_request，可刷新）→ 三级分配
资源与调度层 SCHEDULE 核心：资源协调 + 并发派发 + 失败传播 + 死任务剪枝
资源
Agent 注册表 orchestration/registry.py
能力是问出来的，不是配出来的：info_request 采集 capability / resource / constraint 声明入库（单点失败隔离）。三级分配全程留痕：exact（同 model 多实例轮询）→ capability（部分覆盖标 risk）→ degraded（降级通用 LLM）。连续任务失败达阈值自动摘除。
exact 精确匹配capability 能力匹配degraded 降级留痕失败摘除
调度
调度器（同步 / 异步） scheduler.py · scheduler_async.py
拓扑派发；asyncio 并发推进（FIRST_COMPLETED），资源限制从统计走向执行：per-agent 并发上限（Semaphore）+ 滑动窗口限速。重试 N=2 指数退避 → 耗尽后失败传播 + 反向可达剪枝 → 取消下发（best-effort）。竞态处理：冻结派发 → 逐级取消 → 统一收尾，晚到结果丢弃。
重试 N=2 指数退避反向可达剪枝取消 best-effort竞态：冻结→取消→收尾
派发 task_request / info_request 框架永远主动 · 模板 + 请求 JSON + 上游数据拼接（=== REQUEST === / === INPUT === 分段）
cancel 变体（best-effort）
执行层 EXECUTE 协议装配与解析——稳定性风险在此吸收，agent 侧零适配
适配
Agent 适配器 orchestration/adapters/
base：协议模板装配（完整/简化版 + few-shot 正反例）+ 双层校验解析（提取 → Schema 严格校验 → 失败自动重试一次，与任务重试分离计数）；DeepSeek 适配器走 AsyncOpenAI 真异步，同步适配器经线程化零改动兼容。
模板分档（完整/简化）request_id 强制回带解析重试 + 修正提示
Agent
Agent 池（外部） DeepSeek / Claude / 自建
只接收请求、返回符合 Result 契约的 JSON——不为编排系统做任何适配。框架唯一硬约束：agent 能输出合法 JSON。所有稳定性风险（格式漂移/语义漂移/注入）由框架解析组件吸收。
Result 契约 request_id 对账 · 取消任务晚到结果直接丢弃
治理层 GOVERN 结果审计 + 成本核算 + 可观测性（对账与反馈的数据面）
审计
结果审计器 orchestration/audit.py
正确性对账（状态 vs 契约矛盾/缺契约/晚到结果）+ 分配审计（降级/风险）+ 剪枝审计 + 语义交叉校验（capability / side_effects 声明 vs 实际）。verdict 三级：ok / warning / critical。
成本
成本核算 orchestration/cost.py
按 agent / 匹配类型归集成本与 token（降级成本单独暴露）；失败重试沉没成本、剪枝已发生消耗（先成功后仍被剪）单独列账；对 agent 预算声明做超支判定。
观测
可观测性 orchestration/metrics.py
指标聚合（按 run 隔离：成功率/耗时/峰值并发/降级数）+ 结构化日志（key=value）。指标直接喂审计与学习，日志覆盖请求/响应/解析/取消全链路。
AuditReport / PruneReport 正确性 · 成本 · 剪枝证据（root_failure + pruned 清单）
学习层 LEARN 复盘失败与低效，沉淀规则反哺拆解与分配
学习
学习引擎 orchestration/learning.py
启发式规则提取，阈值可配，产出「证据 + 动作建议」：REC（解析组件排查）/ FP（错误码频发换 agent）/ DEG（降级占比高，核对拆解建议）/ CAP（风险分配失败率高，重采能力）/ BUG（超预算）/ PRU（剪枝复盘拆解并行度）。
规则
规则库 / 经验库
规则带证据链与动作建议，为拆解策略优化、能力声明重采、预算校准提供闭环接口——反馈虚线见右侧。
规则反馈 · 优化拆解策略
