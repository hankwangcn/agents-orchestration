Agents Orchestration — 架构总览

结果导向的 Agent 编排框架（Result-driven Orchestration）· 只管理任务到结果，不观测 agent 内部状态 · 提示词即协议，agent 零适配

接入层 规划层 调度层 执行层 治理层 学习层 持久化底座
主数据流（结果契约驱动） 取消信号（best-effort） 学习反馈闭环
接入层 ACCESS 系统边界
框架对外的全部入口，覆盖目标提交、进度查询、报告获取与执行过程查阅。
API 网关
核心功能框架唯一的 HTTP 服务入口，承载运行全生命周期的对外接口与后台任务管理。
核心逻辑REST 服务，承载目标拆解 POST /api/decompose、任务图提交 POST /api/runs、运行枚举 GET /api/runs、进度快照、收尾报告 GET /api/runs/{id}/report、人读投影 GET /api/runs/{id}/view、叙述摘要 POST /api/runs/{id}/narrative、运行指标、运行取消、断点恢复、人工确认、agent 档案 GET /api/agents 与跨运行经验库 GET /api/lessons；并负责任务的后台执行与生命周期管理。agent 侧通信不经此暴露。
Web 页面
核心功能运行存档的人读界面，完整呈现一次运行的执行过程。
核心逻辑服务端渲染，同源、零构建、零跨域；含运行列表 GET / 与运行详情 GET /runs/{id}，详情呈现过程时间线、任务与结果、分配记录、失败传播、治理结论与学习规则。人读版是运行存档的读时投影——按需渲染、纯函数（同一份存档渲染同一份视图，可重放、零成本），不落盘为第二份真相。
命令行客户端
核心功能接入能力的命令行形态，把框架全部操作暴露到终端与交互式会话。
核心逻辑仅依赖标准库的轻量客户端。子命令覆盖拆解、提交、报告、指标、取消、恢复、人工确认、agent 档案、经验库、运行枚举、运行视图、叙述摘要与服务启动；无子命令时进入交互式会话。
编程式接口
核心功能以库内嵌方式直接驱动编排，供上层程序集成。
核心逻辑提供同步入口（单次运行）与异步入口（并发运行，运行间状态隔离）；以任务图为输入、以调度报告为输出。
提交目标 目标文本 → 拆解引擎；或直接提交现成任务图
规划层 PLAN 目标 → 任务图
将自然语言目标拆解为可执行、可并行、可审计的任务图，并给出任务图的结构视图与可用资源画像。
任务拆解引擎
核心功能把自然语言目标转成带数据流依赖的子任务图。
核心逻辑由大模型完成拆解，产出任务图并执行拆解 Schema 校验与修正重试（重试携带失败原因与正确示例）。每个子任务声明 model / budget / timeout 与能力标签 required_capabilities，作为后续分配依据。提示词结构为“固定指令 → 学习层指导块 → 用户目标”。属框架内部大模型调用，不经消息协议。
依赖分析
核心功能任务图的结构视图，纯结构计算、不持有运行时状态。
核心逻辑覆盖引用合法性、无环检测、拓扑序（并列节点按插入序，保证确定性）、拓扑分层（并行前沿）、最大并行宽度、可达性与反向可达（剪枝判据）与交付点判定；并承担拆解产物的合法性校验。运行时状态归调度层，本模块只读任务图结构。
资源统计器
核心功能经信息请求采集 agent 的能力、资源与约束声明，形成并维护资源画像。
核心逻辑注册 agent 实例，采集能力、资源与约束声明并解析入库，单点采集失败相互隔离。刷新采用池级惰性刷新（画像超过生存期即重新采集，新鲜时零开销）与派发前决策点校验（复核易变的资源与约束维度）；采集受框架侧墙钟上限约束。
任务图 + 能力需求 资源画像驱动三级分配
调度层 SCHEDULE 分配 · 派发 · 收敛
资源协调、并发派发、失败传播与失效任务剪除。
资源协调器
核心功能为每个任务选定 agent 实例。
核心逻辑三级分配策略——精确匹配（同模型多实例轮询分流）→ 能力匹配（部分覆盖标记风险）→ 降级（显式记录）；连续失败达阈值后自动摘除该实例。只读取资源画像，不执行采集。
DAG 调度器（同步 / 异步）
核心功能按拓扑序派发任务并将运行推进到终态。
核心逻辑按拓扑序派发、传递上游结果。异步实现以 asyncio 并发推进（任一任务完成即处理），资源限制由声明转为强制执行：按 agent 的并发上限（信号量）与速率配额（滑动窗口）。单次尝试超过 timeout 由框架强制中断，避免无响应 agent 长期占用并发名额。失败重试 N=2 并指数退避。竞态按“冻结派发 → 取消 → 统一收尾”处理，迟到结果直接丢弃。
失败处理器
核心功能重试 → 失败传播 → 失效任务剪除 → 统一收尾反馈。
核心逻辑该能力跨三层协作，不构成独立模块——剪枝算法属图结构计算，取消下发与派发冻结属调度控制流。剪枝判据为“任务的产出是否仍被最终交付消费”（反向可达）：存活交付点为空则整棵任务图取消。取消为 best-effort，不阻塞收尾。
派发 task_request / info_request 协议模板 + 请求 JSON + 上游输入拼接；框架永远主动
取消变体（best-effort）
执行层 EXECUTE 协议装配 · 解析
协议装配与解析——稳定性风险在此吸收，agent 侧零适配。
Agent 适配器
核心功能装配协议提示词、调用模型并解析结果契约，是框架与 agent 之间的唯一执行入口。
核心逻辑完成协议模板装配（完整版 / 简化版，模板内嵌正反示例）；两级校验解析（提取 → 信封与输出结构校验 → 失败自动修正重试一次，与任务重试分离计数）。提供同步与异步两条调用路径，异步默认将同步实现置于线程池，HTTP 形态实现真异步。从模型 API 响应回填真实用量与耗时。解析组件为框架内最严格的模块。
Agent（外部）
核心功能接收请求、返回符合结果契约的 JSON，不为框架做任何适配。
核心逻辑唯一硬约束是输出合法 JSON；格式漂移、语义漂移与提示注入等稳定性风险全部由框架侧解析组件吸收，agent 保持零适配。
结果契约 request_id 对账；被取消任务的迟到结果直接丢弃
治理层 GOVERN 审计 · 判定 · 核算
确定性审计、运行级语义判定（advisory）、成本核算与可观测性。
结果审计器
核心功能对结果契约与调度事实执行确定性对账。
核心逻辑覆盖正确性对账（状态与结果契约矛盾、缺失契约、迟到结果）、分配审计（降级与风险）、剪枝审计、语义交叉校验（能力声明、副作用声明与实际结果）与错误模式归集；结论分三级 ok / warning / critical。只读、纯函数、结论可重复（可重放）——审计对象是状态机的自洽性，产出内容的正确性交给反思 / 判定处理，两者分离记录。
反思 / 判定器
核心功能以原始目标为唯一基准，判定最终交付是否达成目标（advisory）。
核心逻辑基准只能是运行级目标 goal（子任务描述是框架自产的拆解产物，用作基准即循环论证），子任务结果仅作证据（含失败与剪枝事实）。判定者优先取注册表中声明 judge 能力的独立 agent（能力经信息请求采集，可为异构模型），无则降级自判并标记 independent=false。判定即一次普通 task_request（消息类型零新增），受输出结构强校验与解析重试约束，调用受墙钟超时约束，超时或异常一律收敛为错误码。advisory：只写报告并供学习层消费，不改变状态、不阻断交付、不自动重派；与审计分离记录，成本单列，判定产物不再被判定。
成本核算
核心功能按 agent 与分配方式归集成本与 token。
核心逻辑降级成本单独呈现；失败重试的沉没成本与剪枝已发生成本单独列账；针对 agent 声明的预算上限执行超支判定（预算声明为 0 时不判定）。
可观测性
核心功能按运行隔离的指标聚合与结构化日志。
核心逻辑指标含成功率、耗时、峰值并发与降级数，直接供审计与学习消费；日志覆盖请求、响应、解析与取消全链路。
治理产物附载回运行存档 审计对账 · 成本 · 剪枝证据 · 目标达成度（advisory）
学习层 LEARN 复盘 · 沉淀 · 回馈
确定性复盘 → 证据分级 → 跨运行经验库 → 回馈拆解提示词。
复盘与规则提取
核心功能运行收尾时对同一份报告执行只读复盘，产出分级的规则结论与动作建议。
核心逻辑规则覆盖 REC-1（缺契约 / 状态矛盾，指向框架自身的契约链路缺口）、FP（同错误码频发，建议更换 agent）、DEG-1（降级占比高，核对拆解建议）、CAP-1（风险分配失败率高，重新采集能力）、BUG（实花超预算）、PRU-1（剪枝，复盘并行度）、INT-1（崩溃中断待人工）与 JUD-1 / JUD-2（目标未达成 / 判定未产出结论）。规则带证据强度分级：objective（确定性事实，只读、结论可重放）与 judgment（大模型判定，非确定有成本），禁止同级呈现。复盘为只读动作，异常一律隔离，不阻断运行收尾。
经验库
核心功能将规则落盘并聚合为跨运行摘要，作为后续任务的数据基础。
核心逻辑规则落盘为经验库表（同一运行重跑幂等），按规则标识聚合命中次数、贡献运行数、最高严重度与最近证据——单次运行内的阈值统计意义有限，跨运行复现才是客观依据。出口为 GET /api/lessons 与 ao lessons。
提示词顾问
核心功能生成注入拆解提示词的指导块，是学习闭环的出口。
核心逻辑指导块含三部分——① 注册表实测事实（当前可用模型、已注册能力标签，直接测量无需阈值，可在拆解期即规避降级与能力风险）；② 达复现门槛的客观规则（min_occurrences 默认 2，每条恒附带“既往 N 次运行命中 M 次”的数值依据与建议动作，条数受限、超长截断）；③ 判定结论单独成节并显式标注非确定来源，客观与判定禁止同级呈现。指导块缺失、空串或异常一律退化为不注入，学习层故障不影响拆解。
运行存档落盘 过程事件流 + 终态报告（治理与学习产物附载）
持久化底座 STORE 跨层基础
保存框架侧的调度状态与运行存档，供崩溃恢复、查阅与复盘。
状态存储 / 运行存档
核心功能单次运行的不可变存档，是框架的唯一权威来源。
核心逻辑由过程事件流（状态变更逐条落盘，可精确回放）与终态报告（治理与学习产物附载）构成，事件驱动写入使崩溃点数据最新、丢失窗口近似于零。支持报告读回与运行枚举，跨进程重启后仍可查询与恢复。断点恢复据此执行 A+B 策略：无副作用任务自动重派，声明副作用的任务置为待人工确认。经验库与叙述摘要为该存储的可选能力，实现未支持时退化为无相应记忆。
