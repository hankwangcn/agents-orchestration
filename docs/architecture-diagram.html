Agents Orchestration — 架构总览

结果导向的 Agent 编排框架（Result-driven Orchestration）· 只管理任务到结果，不观测 agent 内部状态 · 提示词即协议，agent 零适配

接入层 规划层 调度层 执行层 治理层 学习层
主数据流（结果契约驱动） 取消信号（best-effort） 学习反馈闭环
接入层 ACCESS 框架对外的全部入口——提交目标、查询进度、获取报告、查看完整执行过程
API
API 网关
FastAPI REST，内置运行生命周期管理：目标拆解 /api/decompose、任务图提交、进度快照、收尾报告、运行枚举 /api/runs、人读投影 /api/runs/{id}/view、运行指标、运行取消、断点恢复、人工确认、agent 档案、跨运行经验库。框架以系统形态对外的 HTTP 入口；agent 侧通信不暴露到 HTTP。
Web
Web 页面 / 人读投影
服务端渲染的运行列表 / 与详情 /runs/{id}（同源、零构建、零跨域）：呈现完整执行过程——过程时间线、任务与结果、分配记录、失败传播、治理结论、学习规则。人读版是运行存档的读时投影（按需渲染、确定性、可复跑），不落盘为第二份真相；叙述摘要（大模型产出）显式触发、单独留档。
PY
编程式接口
库内嵌调用：同步入口（单次运行）与异步入口（并发运行，运行间状态隔离）。
提交目标 目标文本 → 拆解引擎；或直接提交任务图 JSON（API 网关）
规划层 PLAN 将目标拆解为可执行、可并行、可审计的子任务
拆解
任务拆解引擎
由大模型将目标拆解为子任务与数据流依赖，产出任务图，并执行拆解 Schema 校验。每个子任务声明 model / budget / timeout 与能力标签 required_capabilities，作为分配依据。接入：网关 POST /api/decompose、CLI ao decompose --submit；重试携带失败原因与正确示例。属框架内部大模型调用，不经消息协议。
输出：依赖图能力需求声明Schema 校验目标 → 任务图 接入
依赖
依赖分析
任务图的结构视图：数据流依赖，纯结构、不持有运行时状态（状态归调度层）。提供引用合法性、成环检测、拓扑序、拓扑分层（并行前沿）、最大并行宽度、可达性与反向可达（剪枝判据）、交付点判定；承担拆解产物的合法性校验。网关 POST /api/decompose 直接返回结构分析（分层与并行宽度）。
结构视图拓扑分层 = 并行前沿反向可达（剪枝判据）无环 / 引用 / 交付点校验
任务图 + 能力需求 注册表经信息请求采集 agent 能力与资源声明（可刷新）→ 三级分配
调度层 SCHEDULE 资源协调、并发派发、失败传播与失效任务剪除
资源
Agent 注册表
按层切分：规划层资源统计器（注册、信息请求采集、声明解析、惰性刷新）与调度层资源协调器（三级分配、连续失败摘除），注册表收敛为零逻辑转发的组合门面。能力由信息请求采集而非配置：capability / resource / constraint 声明入库（单点失败隔离）。刷新策略为池级惰性刷新与派发前决策点校验（复核易变维度）。三级分配全程记录：精确匹配（同模型多实例轮询）→ 能力匹配（部分覆盖标记 risk）→ 降级（通用模型）。连续失败达阈值自动摘除。
精确匹配能力匹配降级记录失败摘除
调度
调度器（同步 / 异步）
按拓扑序派发；异步实现以 asyncio 并发推进（任一完成即处理），资源限制由声明转为强制执行：按 agent 的并发上限（信号量）与速率配额（滑动窗口）。单次尝试超过 timeout 由框架强制中断（agent 无响应不再占用并发名额）。失败重试 N=2 并指数退避，耗尽后传播失败、反向可达剪枝、下发取消（best-effort）。竞态处理：冻结派发 → 逐级取消 → 统一收尾，迟到结果丢弃。
重试 N=2 指数退避框架侧超时封顶反向可达剪枝取消 best-effort竞态：冻结 → 取消 → 收尾
派发 task_request / info_request 框架永远主动；协议模板与请求 JSON、上游数据拼接（=== REQUEST === / === INPUT === 分段）
cancel 变体（best-effort）
执行层 EXECUTE 协议装配与解析——稳定性风险在此吸收，agent 侧零适配
适配
Agent 适配器
适配器基类：协议模板装配（完整版 / 简化版，内嵌样本示例）、两级校验解析（提取 → 信封与输出结构校验 → 失败自动重试一次，与任务重试分离计数）。DeepSeek 适配器经异步客户端实现真异步；同步实现经线程池零改动兼容。从模型 API 响应回填真实用量与耗时。
模板分档（完整 / 简化）request_id 强制回带解析重试 + 修正提示
Agent
Agent（外部）· DeepSeek / Claude / 自建
只接收请求、返回符合结果契约的 JSON，不为编排系统做任何适配。框架唯一硬约束是 agent 能输出合法 JSON；格式漂移、语义漂移与注入等稳定性风险全部由框架解析组件吸收。
结果契约 request_id 对账；被取消任务的迟到结果直接丢弃
治理层 GOVERN 结果审计（确定性对账）、反思 / 判定（语义达成度，advisory）、成本核算与可观测性
审计
结果审计器
正确性对账（状态与结果契约矛盾、缺失契约、迟到结果）、分配审计（降级与风险）、剪枝审计、语义交叉校验（能力声明、副作用声明与实际结果）。结论分三级：ok / warning / critical。只读、可复跑、确定性——审计对象是状态机自洽性；产出内容的正确性由反思 / 判定处理（两者分离记录）。
判定
反思 / 判定
运行级语义判定：以最终交付与原始目标比对，产出达成结论、评分与缺口。基准只能是 goal（子任务描述为框架自产的拆解产物，用作基准即循环论证），子任务结果仅作证据。判定者优先取注册表中声明 judge 能力的独立 agent（能力经信息请求采集，可为异构模型），无则降级自判并标记 independent=false。判定即一次普通 task_request（消息类型零新增、agent 零变更），受输出结构强校验与解析重试约束。advisory：只写报告并供学习层消费，不改变状态、不阻断交付、不自动重派；与确定性审计分离记录，成本单列。
成本
成本核算
按 agent 与分配方式归集成本与 token（降级成本单独呈现）；失败重试的沉没成本与剪枝已发生成本单独列账；对 agent 的预算声明执行超支判定。
观测
可观测性
按运行隔离的指标聚合（成功率、耗时、峰值并发、降级数）与结构化日志（key=value）。指标直接供审计与学习消费，日志覆盖请求、响应、解析与取消全链路。
治理产物附载回运行存档（落盘） 确定性对账 · 成本 · 剪枝证据（根失败与剪除清单）· 目标达成度（advisory）；治理层与学习层分别对同一份存档写与读
学习层 LEARN 确定性复盘 → 证据分级 → 跨运行经验库 → 回馈拆解提示词
学习
复盘与规则提取
运行收尾时对同一份报告执行只读复盘（审计事实、成本事实、判定结论），产出结论与动作建议：REC（解析组件排查）、FP（错误码频发，建议更换 agent）、DEG（降级占比高，核对拆解建议）、CAP（风险分配失败率高，重新采集能力）、BUG（超预算）、PRU（剪枝，复盘拆解并行度）、INT（断点中断待人工）、JUD（目标未达成或判定链路故障）。规则带证据强度分级：objective（确定性事实，只读可复跑）与 judgment（大模型判定，非确定有成本）禁止同级呈现。学习层是复盘而非主链路，异常一律隔离，不阻断运行收尾。
规则
经验库
跨运行记忆：规则落盘 SQLite（经验库表，同一运行重跑幂等），按规则标识聚合命中次数、贡献运行数、最高严重度与最近证据——单次运行内的阈值统计意义有限，跨运行复现才是客观依据。出口：GET /api/lessons 与 ao lessons。
回馈
提示词顾问
闭环出口为拆解提示词：注入固定指令与用户目标之间的指导块——① 注册表实测事实（可用模型、已注册能力标签，直接测量无需阈值，可在拆解期规避降级与能力风险）；② 达到复现门槛的客观规则（min_occurrences 默认 2，每条附"既往 N 次运行命中 M 次"的数值依据与建议动作）；③ 判定结论单独成节并标注非确定来源。指导块缺失或异常一律退化为不注入，学习层故障不影响拆解。
